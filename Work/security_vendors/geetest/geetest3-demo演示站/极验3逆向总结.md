## 五、三次 w 的生成原理

三次 w 的整体结构一致：`w = base64(AES(明文 JSON)) + RSA(aeskey)`，但明文内容和使用的上下文不同。

### 1. 第一次 w（`calc_w.js`）

```text
aeskey   = 16 位 hex（不存在则现场生成）
指纹串 e = $_BIBC()（浏览器环境采集）
w        = base64(AES(JSON.stringify(指纹对象), aeskey)) + RSA(aeskey)
返回     = { msg(w), aeskey, finger_print }
```

- `aeskey` 与 `finger_print` 会被后续两次 w 复用
- 此阶段主要采集浏览器指纹（UA、平台、插件等）

### 2. 第二次 w（`calc_w2.js`）

关键逻辑：

- **代码格式化检测**：`toString()` 检查函数是否被改写
- **captcha_token**：
  ```js
  token = djb2(code_1 + djb2(code_2) + djb2(code_3))
  ```
- **时序检查**：`100 < Date.now() - t.getTime()` 超时会把指纹字段替换为 `"qwe"`
- 明文字段包括 `light / s / h / hh / hi / vip_order / ct / ep / passtime / rp` 等
- 使用第一次 `get.php` 返回的 `s` 与 `finger_print`
- 最终 `w2 = base64(AES(r, aeskey))`

### 3. 第三次 w（`calc_w3.js`）

明文结构：

```json
{
  "lang": "zh-cn",
  "userresponse": "<H(slide_x, challenge)>",
  "passtime": 841,
  "imgload": 109,
  "aa": "<轨迹压缩编码>",
  "ep": {
    "v": "7.9.3",
    "$_BIT": false,
    "me": true,
    "tm": { "...": "Navigation Timing 的 a~u 字段" },
    "td": -1
  },
  "h9s9": "1816378497",
  "rp": "<md5(gt + challenge[:32] + passtime)>"
}
```

- **aa**：`$_BBEl($_FDd(轨迹), 当前 c, 当前 s)`，把轨迹压缩成方向/位移编码字符串
- **userresponse**：`H(slide_x, challenge)`，把滑动距离编码进字符集
- **ep**：环境指纹，`tm` 真实来源是 `window.performance.timing`
- **h9s9**：动态文件 `gct.js` 执行一系列检测后生成（10 位随机数）；官方 demo 实测固定为 `1816378497`，可直接固定
- 使用**第二次 `get.php`** 返回的新 `challenge`、`c`、`s`
- `w3 = base64(AES(JSON, 新 aeskey)) + RSA(新 aeskey)`

### 混淆家族

- `fullpage.9.2.0`：**Jscrambler**（RPO + 控制流平坦化 CFF）

| 轮次 | 变换 | 结果 |
|---|---|---|
| step1 | 解码器别名识别、字符串还原、状态 token 规范化 | 4802 字符串、471 token、1782 别名 |

## 七、图片乱序与缺口识别

### 乱序还原

极验背景图按固定置换表 `Ut`（52 个索引）重排：

```js
Ut = [39,38,48,49,41,40,46,47,35,34,50,51,33,32,28,29,27,26,36,37,31,30,
      44,45,43,42,12,13,23,22,14,15,21,20,8,9,25,24,6,7,3,2,0,1,11,10,4,5,19,18,16,17]
```

`util.restore_image()` 按该表把 260×160 的图片切块拼回。

### 缺口识别

- **不要用** `TM_CCORR_NORMED + alpha mask`：本案例会匹配到背景右侧亮色区（如 `(192,80)`），导致 `fail`
- **推荐**：Canny 边缘 + `TM_CCOEFF_NORMED`
- 可用 `ypos` 校验：缺口垂直中心 ≈ ypos
- 浏览器对照法：直接对 canvas 的 `geetest_canvas_bg` 与 `geetest_canvas_fullbg` 做像素差分，可得到绝对精确的缺口位置

## 八、轨迹生成

`util.get_gt3_slide_track(distance)`：

- `ease_out_expo` 生成 x 位移曲线
- 步数 `78 + distance / 2`，时间间隔 10–20ms
- 返回 `(slide_track, total_time)`
- `slide_track` 第一项为随机负起点，最后一项为 `[distance, 0, total_time]`

轨迹质量直接影响风控，建议结合真人"录制"轨迹库（参考 `Ais137/Recorder`）做多样化。

## 九、踩坑清单（按踩坑顺序）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `TypeError: Cannot read properties of null (reading 'slice')` | 键名拼错：`second_get_resp_dict.get('challange')` | 改为 `'challenge'` |
| 2 | ajax 返回 `fail` | `get_slide_x` 用 `TM_CCORR_NORMED+mask` 匹配到错误位置 | 改用 Canny + `TM_CCOEFF_NORMED` |
| 3 | ajax 返回 `forbidden` | `aa` 用了第一次 `get.php` 的 `s/c` | 改用**第二次** `get.php` 的 `c/s`（原版 `3_slide.js:3460`） |
| 4 | 第七步随机「登录失败」 | `geetest_seccode` 中的 `\|` 未 URL 编码 | 用 dict 提交，让请求库编码成 `%7C` |
| 5 | `download_img` 偶发失败 | 无超时、无重试、不校验响应 | 15s 超时 + 3 次重试 + 双域名交替 + 图片魔数校验 |
| 6 | ep 时间线不符合规范 | 旧版 `tm` 把 `fetchStart~connectEnd` 排在 `unload` 之后逐级递增 | 按 `performance.timing` 真实字段顺序构造 |

> 第 4 条是「有时成功、有时失败」的真正原因，与运行频率、UA、代理无关（冷却、`impersonate="chrome"`、代理均实测无效，只有 URL 编码修复后连续 3 次稳定成功）。

## 十、返回语义与判定标准

| 接口 | 返回 | 含义 |
|---|---|---|
| `ajax.php`（第六步） | `{'success':1,'message':'success','validate':...}` | **w3 纯算通过**，这是逆向成功的判据 |
| `ajax.php` | `{'success':0,'message':'fail'}` | 滑块位置 / userresponse / 参数错误 |
| `ajax.php` | `{'success':0,'message':'forbidden'}` | `aa` 轨迹结构或加密参数被拒 |
| `ajax.php` | `{'success':0,'message':'abuse'}` | 触发滥用检测 |
| `validate-slide`（第七步） | `{"status":"success","info":"登录成功"}` | 业务侧二次校验通过 |
| `validate-slide` | `{"status":"fail","info":"登录失败"}` | 二次校验失败，优先检查提交参数编码 |

## 十二、经验与后续优化

### 经验

1. **先跑通请求链，再抠算法**：三次 w 的调用链不同，但加密结构一致，扣代码时可复用 AES/RSA/Base64 模块
2. **逐字段对照原版**：用解混淆后的 `3_slide.js` 核对每个字段的来源，避免"看起来对、实际用错 s/c"
3. **差分实验定位风控**：同一份代码只改一个变量（编码方式、s/c 来源、匹配算法）跑对照，比猜测有效
4. **浏览器是最终裁判**：用 canvas 差分、hook `encodeURIComponent`、hook `jQuery.ajax` 拿到真实输入，逐字节对比
5. **区分接口语义**：`fail` / `forbidden` / `abuse` 对应不同层级的校验，不要混为一谈

### 可继续优化

- AST：继续消除逗号表达式、常量折叠、内联小函数，进一步提升可读性
- 轨迹：引入真人轨迹库，按距离/设备自适应采样
- ep：将 `tm` 改为按实际页面生命周期动态生成，`h9s9` 保留固定值即可
- 工程化：把 `execjs` 换成常驻 Node 服务，避免每次 `compile` 的开销
- 复用：将 AES/RSA/Base64 抽象为公共模块，三个 `calc_w*.js` 共用
