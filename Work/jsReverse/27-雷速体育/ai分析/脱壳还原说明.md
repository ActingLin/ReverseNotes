# 阿里云 WAF JS 挑战脱壳还原笔记 (雷速体育)

## 一、这是什么

`../demo.html` 是阿里云 WAF 反爬虫的 **JS 验证挑战页**。流程:

1. 访问被保护站点 → WAF 拦截,返回这段 HTML
2. 浏览器执行混淆 JS,结合**环境指纹**算出一个值
3. 写入 `acw_sc__v2` cookie(1 小时有效,`path=/`)
4. 自动 `reload` 重新请求,第二次带上 cookie 即放行

目标:读懂混淆 JS,复现 `acw_sc__v2` 的生成算法。

## 二、壳的结构

混淆 JS 是一个大 IIFE `(function xXRQBR() {...}())`,包含四层保护:

| 组件 | 作用 |
|------|------|
| `Z()` | 加密字符串表(126 个密文,Base64 变体表 + LCG 异或流) |
| `d()` | 字符串解密器,`d(0x240)` → 明文,靠 `vL` 偏移与调用栈 `a` 干扰 |
| `vy()` / `vr()` | **反篡改校验**:`vL = v(源码子串 + typeof window['xXRQBR']) - 329294929`,环境/源码一变 `vL` 就错 → 解密全乱 |
| `a.push(175)/pop()` | 调用栈深度检测,解密器的 LCG 种子取 `a[a.length-1]`(恒为 175) |

关键理解:**`vL` 是解密的"钥匙"**。所有常量运算都 `+ vL`,解密器读密文的起始位 `M = -239 + vL` 也依赖它。把 JS 拷到别的环境(或美化/插桩),`xXRQBR.toString()` 变了 → `vL` 错 → 解出乱码 → 死循环。这就是防拷贝/防篡改的核心。

## 三、破壳关键:vL = 239

### 3.1 缩小范围

解密器 `X` 里把字节转十六进制时调用了 `H.charCodeAt(j).toString(radix)`,而 **JS 的 `Number.toString(radix)` 要求 radix ∈ [2, 36]**:

```
radix = -0x25b + 0x1cd8 + -0x2012 + vL = -223 + vL
=> vL ∈ [225, 259]
```

### 3.2 暴力搜索

对 vL ∈ [225, 260],在 vm 里执行插桩版,检查解密出的明文是否可读英文:

- vL=225~238:死循环,明文乱
- **vL=239:解密出 145 条英文明文,shuffle 循环正常 break** ✅
- vL=240+:明文又变乱/空

> 注:曾尝试"离线计算 vL"(提取 `v()` 哈希函数对源码子串做哈希),但结果 1681121324 与真实值 239 差很远,说明该方法不可靠(环境/提取差异),最终以暴力搜索为准。**搜索约束来自 radix 范围,这是最硬的抓手。**

## 四、解密器原理(已还原)

解密器是 **Base64 变体 + LCG 流密码**:

```js
// 标准最小随机数发生器 (minstd)
const MOD = Math.pow(2, 31) - 1;   // 2147483647
const MUL = 0x12a02 - 0x14e19 + 0x32a * 0x47;  // 48271
const INC = 0;                                 // H = 0
const SEED = 175;   // a 数组栈顶, 调用栈检测的产物

function makeRand() {
  let W = SEED % MOD;
  function s() { W = (MUL * W + INC) % MOD; return W; }
  return function () { return s() % 64; };   // 0~63
}

// 解密一个密文: 每位 e.indexOf(c) ^ 随机数
const BASE64 = 'ISrhX5i4vsENygf/0FDWRJPOucoaAUpe78mdnTL+3zBGZM9qbkYwKl2QjtV1Cx6H=';
// 读密文从 M = -239 + vL = 0 开始, 每字符 e.indexOf(c)^s() 得到字节值
// 拼出字节串后 %XX 编码再 decodeURIComponent
```

## 五、还原后的核心算法

### 5.1 字符串明文(部分关键)

| index | 明文 | 用途 |
|------|------|------|
| 0x1f1 | `0123456789` | 字符表 |
| 0x203 | `ABCDEF` | 字符表 |
| 0x23c | `1234cf0d46` | **cookie 盐值前缀** |
| 0x251 | `arg1` | 取页面参数 |
| 0x252 | `slice` | |
| 0x230 | `webdriver` | 反爬检测 |
| 0x23b | `SVGAnimate` | 制造错误对象 |
| 0x24c+0x254 | `stackTrace`+`Limit` | Error.stackTraceLimit |
| 0x1f1/0x210 | `toString`/`toLowerCas` | 方法名 |
| 0x214+0x? | `String` | |
| 0x1ef | `toString` | |
| 0x206 | `undefined` | typeof 比较 |
| 0x20e/0x216 | `sWBMO`/`zNjlP` | 随机属性键 |
| 0x210/0x221 | `toLowerCas`+`e` | `toLowerCase` |

### 5.2 环境指纹采集 `s()`

```js
function s() {
  var M = Error["stackTrace"+"Limit"];              // Error.stackTraceLimit
  try {
    Error["stackTrace"+"Limit"] = 0;
    z['w']["SVGAnimate"+"String"]();                // 调用不存在的构造器, 制造无堆栈错误
  } catch (j) {
    var F = j["name"] + ' ' + j["stack"];           // 抓错误 name + stack
    var t = new RegExp('\b[\w\/:\-\[\]<]{4,}[^\d:@]\b', 'gm');
    return F["match"](t)["map"](seg => W(seg, false)); // 对每段调用哈希 W()
  } finally {
    if (M) Error["stackTrace"+"Limit"] = M;         // 恢复 stackTraceLimit
  }
}
```

> 用途:检测 `Math.random.toString()` / `Function.prototype.toString` 是否被 hook(对比 `"function random() { [native code] }"` 片段),并把堆栈信息哈希进指纹。

### 5.3 随机数种子

```js
Math["random"] = c( W( JSON.stringify(S) ) );
```

`S` 是三个大数组成的数组(经 shuffle 重排),`W()` 是 64 位哈希,结果作为 LCG `c()` 的种子 → **`Math.random` 被替换成由环境指纹决定的伪随机序列**。这就是为什么每次访问页面,相同环境得到相同随机序列。

## 六、acw_sc__v2 生成公式(核心结论)

```
O = arg1.slice(0, 40).split('')          // 页面参数 arg1 的 40 个字符
M = matrixShuffle(O).join('')            // 矩阵换位洗牌 (case'3')
M += [环境布尔].map(随机两位hex)          // 环境检测数组逐位随机 (case'5')
M = "1234cf0d46" + "-" + M.toLowerCase() // 盐值 + 随机串 (case'0')
reload(M)  →  setCookie("acw_sc__v2", M)
```

其中随机数由**种子化 Math.random**(§5.3)驱动。

**验证**:脱壳插桩版在 Node 中跑通,算得
`acw_sc__v2 = "1234cf0d46-a755549e6c2dbda1fb6ca1388aff18b2a247d5e2660e670704"`

## 八、踩坑记录

1. **vL 设 0 或错误值 → 字符串表 shuffle 循环死循环 + 内存暴涨**(vm 需加 timeout)
2. **环境缺 `arg1`**:xXRQBR 内部 `window['arg1'].slice(0,40)` 访问 ../demo.html 明文脚本定义的全局 → 补 `ctx.arg1` 才跑通
3. **`Number.toString(radix)` 范围约束**是破 vL 的最硬抓手
4. 字符串"截断"(如 `toLowerCas`)是**混淆器切词**,拼接后才是完整字符串,属正常
5. Node 环境算出的 cookie 与真实浏览器**数值不同**(随机种子依赖环境指纹),但**算法结构**一致

## 九、线上实践补充 (重要修正)

脱壳后用 `../demo/team_info.py` 实际请求雷速体育接口,有两点更稳的做法:

1. **原版 JS 直接跑,无需硬编码 vL=239**。线上返回的 WAF JS 是**压缩版**(`function vr(){return vL=vy(...),'oTP+ef0';}` 无空格),源码与脱壳的 demo.html(美化版)不同,`vL` 的真实值也不同。但只要在 Node vm 里**补全环境**——`window`/`globalThis`/`navigator`/`arg1`(从挑战页 `renderData.l1` 动态提取)——`vy()` 会**自行算出正确的 vL**。验证:线上压缩版原样执行即算出 `1234cf0d46-...`。
   - 这推翻了"必须替换 vr()"的结论:脱壳时最初的死循环,根因是**缺 `arg1` 环境**导致 `window['arg1'].slice` 抛错被吞、连锁死循环,而非 vL 计算失败。
2. **arg1 每次挑战都变**,必须从**本次响应**的 `renderData.l1` 里提取(`l1.split("'")[1]` 等价于 JS 的 `slice(10,60)`),不能写死。
3. 请求头里的 `accept` 是**签名值**(由 `demo.js` 的 `buildSignedHeaders` 生成),缺失时服务器直接回 204,连挑战页都不给。

完整接入见 `../demo/team_info.py`:
```
Session 请求 → 返回挑战页 → 提取 arg1 + WAF JS → Node vm 补环境执行 → 得 acw_sc__v2
→ 种入 Session(domain='.leisu.com') → 重试请求 → WAF 放行
```
