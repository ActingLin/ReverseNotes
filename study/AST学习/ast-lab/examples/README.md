# AST 反混淆实例集（可运行）

> 这是 `study/AST学习/` 的配套代码。每个文件都是**独立可运行**的，
> 边跑边看输出，比只看文档快 10 倍。

## 怎么跑

```bash
cd "study/AST学习/examples"

# 直接运行任意一个例子，它自己会打印"变换前 / 变换后 / 中间日志"
node 01-hello.js
node 06-string-array.js
```

依赖说明：本项目根目录（`ReverseNotes/`）已经装好了
`@babel/parser`、`@babel/traverse`、`@babel/types`、`@babel/generator`，
Node 会向上查找 `node_modules`，所以**不需要额外安装**。

## 每个例子的统一结构

所有脚本都遵循同一个"教学模板"：

1. **头部注释**：这个例子解决什么真实问题、难点在哪、思路是什么
2. **原始代码**：一段模拟真实混淆形态的输入
3. **分步骤处理**：每一步都有 `console.log` 告诉你"现在在干什么、发现了什么"
4. **结果对比**：变换后的代码 + 实际运行验证
5. **尾部注释**：为什么这么写、常见坑、真实场景的变体

## 建议的用法

**第一遍：直接跑，看输出**
不急着读代码，先看"混淆代码 → 清晰代码"的效果，建立信心。

**第二遍：对着输出读代码**
每读一行就问自己："这行如果不写会怎样？"（脚本注释里大部分给了答案）

**第三遍：自己改坏它**
这是最有效的学习方式：
- 把 05 的 `exit` 改成 `enter`，看结果怎么变（体会遍历顺序）
- 把 06 的 `try-catch` 删掉，看会不会崩（体会异常防御）
- 把 06 的清理循环改成只跑一轮，看数组还在不在（体会固定点迭代）
- 把 07 的 IIFE 执行去掉，看还原结果错成什么样（体会位移的杀伤力）

**第四遍：拿真实代码练**
去 52pojie、GitHub 找真实混淆样本，或者用
[obfuscator.io](https://obfuscator.io) 自己生成一份混淆代码来还原。
