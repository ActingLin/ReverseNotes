## 一、5 分钟快速开始（先看到效果，再学原理）

```bash
cd "study/AST学习/examples"
node 06-string-array.js
```

你会看到一段"天书"被还原成人话：

```
还原前：console[_0x5e1b(0)](_0x5e1b(1));
还原后：console.log("hello world");
```

**这就是 AST 反混淆在做的事。** 看到效果之后再回头学原理，动力会强很多。

## 三、三条学习路线（按你的目的选）

### 路线 A：我是小白，想系统学会（推荐主线）

```
00（本文）→ 01 → 02 → 03 → 04 → 05 → 06
             ↓    ↓    ↓    ↓
           examples 对应实例（边看边跑）
```

**时间预期**：每天 1-2 小时，一周能走完并建立完整认知。

每个阶段的验收标准：

| 阶段 | 读完 | 你应该能做到 |
|------|------|-------------|
| 入门 | 01 + 例 01~02 | 看懂任何 AST 脚本的骨架；会用 AST Explorer 查节点 |
| 基础 | 02 + 例 03~05 | 处理字符串/常量类混淆；理解 exit、作用域、引用计数 |
| 核心 | 03 + 例 06~07 | 还原 90% 的 obfuscator.io 样本（含数组位移） |
| 进阶 | 04 + 例 08 | 处理基本的控制流平坦化 |
| 补漏 | 05 + 06 | 知道哪里有坑、边界在哪、什么工具能用 |

### 路线 B：我只要解决手上这一个样本

```
05-难点与避坑指南.md（先看"认知层"三条，避免使错劲）
  → examples/README.md（找到和你样本最像的实例）
  → 改那个实例去适配你的样本
  → 卡住了回 05 查坑
```

### 路线 C：我想先搞懂"这东西有没有用"再决定学不学


## 四、这套资料的设计逻辑（为什么这样组织）

学习 AST 反混淆最容易踩的三个坑，这套资料的编排就是针对它们的：

### 坑 1：只看理论，不动手 → 学了就忘

**对策**：`examples/` 里 8 个实例**全部可运行**，
每个脚本都打印"处理前/处理中/处理后"。**先跑，再读，再改。**

### 坑 2：只学"怎么做"，不懂"为什么" → 换个样本就抓瞎

**对策**：每篇文档都专门解释**动机**：
- 为什么常量折叠必须写在 `exit`？（自底向上）
- 为什么清理要"循环到不再变化"？（固定点迭代）
- 为什么数组位移不能心算？（要执行，因为混淆器的表达式可能很复杂）

**理解"为什么"的人，能处理没见过的变体；只记"怎么做"的人，只能处理见过的。**

### 坑 3：不知道"学到什么程度算够" → 无限投入或过早放弃

**对策**：《05-难点与避坑指南》开篇第一件事就是讲**目标管理**：
先定义你要什么（看懂逻辑？替换运行？提取算法？），再决定还原到什么程度。

## 六、学完之后做什么

1. **改坏再修好**：`examples/README.md` 里列了 4 个具体的"改坏"实验
2. **自己出题**：用 obfuscator.io 生成样本，从零还原一遍
3. **啃源码**：[MadLongTom/JS-AST-Deobfuscator](https://github.com/MadLongTom/JS-AST-Deobfuscator)（干净易读）
4. **上真实战场**：52pojie 的"脱壳破解区-代码混淆"版块有大量实战帖
5. **工程化**：研究本机的 `ast-deobfuscate` skill，学"插件 + visitor 分层"的工程做法
6. **回到逆向主线**：AST 只是逆向的一环，把它接到完整流程里
   （抓包 → 定位 → **还原** → 理解 → 复现 → 工程化）
