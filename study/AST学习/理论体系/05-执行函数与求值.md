> 上一篇：[04-节点转代码](./04-节点转代码.md) ｜ 下一篇：[06-函数作用域与绑定](./06-函数作用域与绑定.md)

## 1. 为什么反混淆需要"执行"？

字符串数组位移不能心算、解密函数是普通 JS 逻辑（Base64/RC4/异或），**与其静态重写算法，不如直接运行它拿结果**。三条路线，由易到难：

| 路线 | 手段 | 适用 |
|------|------|------|
| ① 静态求值 | `path.evaluate()` | 纯常量表达式（`0x42e * -0x6 + 0x25c8`、`!![]`） |
| ② 沙箱执行 | Node `vm` 模块 | 解密函数/数组位移等**纯 JS、无浏览器依赖**的片段 |
| ③ 浏览器执行 | 补环境 / hook | 依赖 `window`/`document` 的代码 |

## 2. 路线一：path.evaluate() 静态求值

Babel 自带静态求值，返回 `{ confident, value }`：

```js
traverse(ast, {
  BinaryExpression(path) {
    const { confident, value } = path.evaluate();
    if (confident) {
      // 表达式中全是静态值（无变量、无调用），可安全折叠
      if (typeof value === "string") path.replaceWith(t.stringLiteral(value));
      else if (typeof value === "number") path.replaceWith(t.numericLiteral(value));
      else if (typeof value === "boolean") path.replaceWith(t.booleanLiteral(value));
    }
  }
});
// 0x42e * -0x6 + 0x25c8 + -0xcb4  → 折叠为数字
// !![]                              → true（不透明谓词消除）
```

**原理**：evaluate 递归检查子节点，全部是静态字面量且不依赖运行时才能 `confident: true`；出现变量引用、函数调用、环境依赖（`window` 等）就 `deopt`（放弃）。

**适用/不适用**：
- ✅ 数值/字符串/布尔常量表达式折叠、不透明谓词（`x² ≥ 0` 恒真类）
- ❌ 解密函数调用 `_0xae0a('0x1')`——调用依赖函数体，evaluate 不会帮你执行，必须走路线 ②③

## 3. 路线二：Node vm 沙箱执行

### 3.1 API 要点

```js
const vm = require('vm');

const sandbox = { /* 想暴露给沙箱的变量 */ };
const ctx = vm.createContext(sandbox);   // 把 sandbox "上下文化"，拥有标准全局内置对象

const result = vm.runInContext('1 + 2', ctx);           // 在指定沙箱执行，返回结果
const result2 = vm.runInNewContext('1 + 2', sandbox);   // 每次新建沙箱执行
// 被执行的代码无法访问本地作用域
```

### 3.2 实战模式：两段式执行（ScamClub 恶意软件分析案例）

沙箱不会替你"补全上下文"，所以解密函数的执行分两段：

```
① 先执行【声明】代码 → 函数进入沙箱上下文
② 再执行【调用】代码 → 拿到返回值
```

```js
const fs = require('fs');
const vm = require('vm');
const parser = require('@babel/parser');
const traverse = require('@babel/traverse').default;
const generate = require('@babel/generator').default;
const t = require('@babel/types');

const code = fs.readFileSync('obf.js', 'utf-8');
const ast = parser.parse(code, { sourceType: 'unambiguous' });

// ── 第一步：收集"字符串数组 + 解密函数"片段 ──
let decryptFuncCode = null;   // 解密函数源码（用 04 篇的 path.toString() 提取）
let arrayCode = null;         // 字符串大数组的声明源码

traverse(ast, {
  VariableDeclarator(path) {
    // 识别大数组：init 是 ArrayExpression 且元素都是字符串
    if (path.node.init && path.node.init.type === 'ArrayExpression' &&
        path.node.init.elements.every(e => e.type === 'StringLiteral')) {
      arrayCode = path.parentPath.toString();   // var _0x5e1b = ['a','b',...];
    }
  },
  FunctionDeclaration(path) {
    // 识别解密函数：特征自定（如参数为索引、返回值是数组元素）
    if (path.node.params.length >= 1) {
      decryptFuncCode = path.toString();
    }
  }
});

// ── 第二步：沙箱执行 ──
const ctx = vm.createContext({});
vm.runInContext(arrayCode, ctx);          // 声明数组：ctx 里现在有 _0x5e1b
vm.runInContext(decryptFuncCode, ctx);    // 声明解密函数
// 现在 ctx 里的解密函数可以随时被调用：
const decrypt = (idx) => vm.runInContext(`_0x5e1b_func(${JSON.stringify(idx)})`, ctx);

// ── 第三步：遍历所有调用点，执行后替换 ──
traverse(ast, {
  CallExpression(path) {
    if (path.node.callee.name !== '解密函数名') return;
    const arg = path.node.arguments[0].extra.rawValue;
    const value = decrypt(arg);           // 沙箱里执行解密
    path.replaceWith(t.valueToNode(value));
  }
});

fs.writeFileSync('output.js', generate(ast).code);
```

> 把函数提取出来先 `generate` 成字符串、再 `runInContext` 注入，是"执行还原"的标准套路。更省事的方式：直接 `vm.runInContext(generate(ast).code)` 把**整份混淆代码**跑进沙箱，让解密函数/数组自己就位，再逐个调用。

### 3.3 浏览器环境依赖怎么办 → 补环境

解密函数里出现 `window`/`document`/`navigator` 时，沙箱里没这些对象。两条路：

1. **主动补**：执行前往 sandbox 塞 `{ window: {}, document: { createElement: () => ({}) }, navigator: { userAgent: '...' } }`，报错缺什么补什么。
2. **Proxy 惰性补**（更优雅）：用 `new Proxy({}, { get: () => new Proxy({}, ...) })` 让任何属性访问都返回一个"万能对象"，避免逐条补。

### 3.4 路线三：浏览器 hook 执行

依赖真实浏览器行为（DOM、事件、环境检测）时，别硬补：

- 在浏览器 DevTools 或 Frida/油猴脚本里 **hook 解密函数**，直接打印输入输出对；
- 用 Playwright/CDP 跑真实页面，`evaluate_js` 调解密函数批量拿结果（本项目 MCP 也有对应能力）；
- 拿到"索引 → 明文"映射表后，回到 AST 里做静态替换。

## 4. 安全警告（必读）

> Node 官方文档明确：**"The node:vm module is not a security mechanism. Do not use it to run untrusted code."**

- **Context 逃逸**：沙箱代码可通过 `this.constructor.constructor`（即 `globalThis.constructor`）拿到宿主上下文的 `Function` 构造函数，进而在**你的 Node 进程全局作用域执行任意代码**。
- vm2 用 Proxy 拦截来防护，但仍有漏洞（如 CVE-2023-3790）。
- **对策**：① 只跑你已知的、来自自己逆向目标的解密片段（不是不可信输入）；② 真要跑不可信代码，放**独立子进程**里，失败/超时就杀掉。

## 5. 常见坑

| 问题 | 原因 | 解决 |
|------|------|------|
| `setTimeout(()=>{...})` 返回 undefined | 沙箱等不到异步回调 | 预处理剔除 `setTimeout/setInterval/Promise` 再用同步逻辑；或 vm2 开 `timer: true` |
| 替换后代码报 `_0x1234 is not defined` | 字符串还原了，但映射表数组声明残留 | 开死代码剔除（DCE）删掉未引用的 `VariableDeclarator` |
| 解密结果与浏览器不一致 | 环境检测分支（UA、平台）走了不同路径 | 沙箱里把关键环境变量补成与目标浏览器一致的值 |
| 跑一次死循环/卡死 | 解密函数有反调试死循环 | 加超时子进程执行，超时直接 kill |

## 6. 三条路线选择策略

```
表达式能 evaluate（confident:true）？
  ├─ 是 → ① 静态求值（最快最安全，永远优先）
  └─ 否 → 代码是否纯 JS、无浏览器依赖？
           ├─ 是 → ② vm 沙箱（快，注意逃逸风险）
           └─ 否 → ③ 浏览器 hook/补环境框架（最重但最真）
```

> 实际经验：**优先 ①，主力 ②，③ 只在环境检测型样本上兜底**。同一份混淆代码里三种路线经常混合使用。
