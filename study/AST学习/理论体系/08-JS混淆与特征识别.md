### 5.1 混淆的本质

**JS 混淆不是加密**——它没有密钥，而是通过"语义遮蔽"和"控制流扭曲"提高代码阅读门槛。混淆代码依然可执行，逆向的目标是系统性地重建语义、恢复控制流、映射变量关系。

### 5.2 Obfuscator.io 四大核心混淆机制（逆向必会）

Obfuscator.io 是目前 GitHub Star 数最高、配置最全的开源 JavaScript 混淆器：

1. **字符串数组（String Array）**：将所有字面量字符串存入全局大数组，用动态索引+解密函数（如 `_0xae0a('0x1')`）取用。元素可能是明文、Base64 编码或 RC4 加密密文，配合自执行函数（含 `push`/`shift` 关键字）进行数组位移。
2. **控制流扁平化（Control Flow Flattening）**：将线性执行逻辑打散为 `while(true) { switch(状态变量) { case... } }` 状态机，核心逻辑被稀释在大量垃圾分支中。
3. **标识符混淆**：变量/函数名替换为无意义十六进制短名（如 `_0x1a2b`）。
4. **死代码注入**：插入永不执行的冗余分支，以及作用域污染（IIFE 嵌套）。

**典型特征**：
- 大数组 + 自执行函数 + 解密函数
- 解密函数中出现 `'abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789+/='` 说明有 Base64 编码
- 函数名/变量名以 `_0x` 或 `0x` 开头

### 5.3 混淆类型特征速查表

| 混淆类型 | 核心特征 | 还原方法 |
|---------|---------|---------|
| **Obfuscator.io (OB)** | 变量名 `_0x...`、大数组+位移、while+switch 状态机 | AST 反混淆（见 09 篇） |
| **Eval 混淆（packed）** | `eval(function(p,a,c,k,e,d)...)` 包裹长字符串 | 去掉 eval 后控制台输出 / 在线解包 |
| **AAEncode（颜文字）** | 主体由颜文字（`ω`、`Θ`、`ﾟ∀ﾟ`、`ﾟωﾟ`）组成，以 `(ﾟ∀ﾟ)` 开头，`('_')` 结尾 | 去掉末尾 `('_')` 加 `toString()` 输出；或 hook Function/eval |
| **JJEncode（$混淆）** | 大量 `$`、`_` 符号，以 `$~[];` 开头 | 去掉末尾 `()` 加 `toString()` 输出；或 hook Function/eval |
| **JSFuck（六字符）** | 仅由 `[` `]` `(` `)` `+` `!` 六种字符组成，代码极长 | 控制台直接执行；jsdec.js.org / v_jstools 一键还原 |
| **Webpack 混淆** | 模块包裹 `(function(modules){...})([function(module,exports){...}])` | AST 重写处理 bundles |
| **控制流平坦化** | 外层 `while(true)` + 巨大 `switch` + 状态变量 | AST 控制流还原（见 09 篇 6.4） |
| **自定义混淆/变种** | 无固定特征 | 结合 AST 插件动态适配 |

### 5.4 补充：不透明谓词与分层混淆（2024-2025 新趋势）

- **不透明谓词（Opaque Predicate）**：结果恒真/恒假但看起来像"真条件"的表达式，如 `x² ≥ 0`、`!![]`、`"a" === "a"`。用于插入**假分支**（永不执行的死代码）或给控制流还原"下套"。识别方法：`path.evaluate()` 静态求值（见 [05 篇](./05-执行函数与求值.md)）。
- **分层混淆（Opaque-CFF 组合）**：控制流平坦化 + 不透明谓词叠加，分析者必须**同时**解开 dispatcher 并识别假分支。这是近年混淆器的防御升级方向，纯规则式还原难度大增。

### 5.5 通用识别与调试思路

1. **特征对照**：根据代码外观快速判断混淆类型（颜文字→AAEncode；大量 `$`→JJEncode；仅 6 字符→JSFuck；`_0x`→OB 系）。
2. **控制台直接运行**：浏览器能看懂混淆代码，直接执行即可解开（AAEncode/JJEncode/JSFuck 均适用）。
3. **hook Function / eval**：AAEncode/JJEncode 等通过 `Function` 构造函数或 `eval` 执行源码，hook 后从 `arguments` 中可查看源码。
4. **在线工具**：[jsdec.js.org](https://jsdec.js.org) 支持自动识别混淆类型并一键还原；v_jstools 插件可用于 JSFuck 等场景。
5. **单步调试**：若运行报错，可截取部分代码主动令其出错，单步调试观察代码行为；复杂混淆需结合 AST 技术处理。
