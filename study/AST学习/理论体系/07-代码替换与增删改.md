## 1. 方法总览表

| 方法 | 用途 | 参数要求 |
|------|------|---------|
| `replaceWith(node)` | 替换为**单个**节点 | 单个 node，**不能是数组** |
| `replaceWithMultiple(nodes)` | 替换为**多个**节点 | 节点数组；表达式位置必须是语句 |
| `replaceWithSourceString(code)` | 用源码字符串替换 | 字符串（内部解析为 AST，**效率低不推荐**） |
| `insertBefore(node)` / `insertAfter(node)` | 前后插入兄弟节点 | Statement 或 Statement 数组 |
| `unshiftContainer(key, node)` / `pushContainer(key, node)` | 向 `body` 等数组属性头部/尾部插入 | (属性名, 节点) |
| `remove()` | 删除当前节点 | 无 |
| `dangerouslyRemove()` | 传入 falsy 节点时的删除 | 无 |

## 2. replaceWith：替换为单个节点

```js
BinaryExpression(path) {
  if (path.node.operator === "*" && path.node.left.name === path.node.right.name) {
    path.replaceWith(t.binaryExpression("**", path.node.left, t.numericLiteral(2)));
  }
}
// 输入: let square = n => n * n
// 输出: let square = n => n ** 2;
```

**要点**（来自 Babel 源码行为）：
- 返回值是**新节点的 NodePath 数组**（可继续操作）
- 传 **falsy**（null/undefined）→ 报错，提示改用 `dangerouslyRemove()`；传**数组** → 报错，提示改用 `replaceWithMultiple()`
- **Program 根节点**只能替换为 Program
- **内置启发式转换**：语句位置自动把 Expression 包成 `expressionStatement`；表达式位置自动把 Statement 转成表达式（`replaceExpressionWithStatements`）——所以"用多个语句替换一个表达式"也能工作，但结果可能包成 IIFE
- 替换**父节点**：`path.parentPath.replaceWith(...)`

## 3. replaceWithMultiple：替换为多个节点

```js
ReturnStatement(path) {
  if (path.node.argument.type === "BinaryExpression") {
    path.replaceWithMultiple([
      template(`let a = N`)({ N: path.node.argument.left }),
      template(`return 4 * a`)()
    ]);
  }
}
// 输入: let square = n => { return n * n; }
// 输出: let square = n => { let a = n; return 4 * a; }
```

> **注意**：在**表达式位置**（如 `var x = <这里> + 1`）用多个节点替换时，这些节点**必须是 Statement**。Babel 的启发式算法在表达式位置塞多条语句时会做特殊处理，结果不一定符合直觉——表达式位置想变多语句，正确做法是**提升到语句层面**（在父语句处操作）。

## 4. replaceWithSourceString：不推荐

```js
path.replaceWithSourceString(`function foo() {}`);
```

内部每次都要 `parse` 一遍字符串，**效率低**；除非处理动态源码字符串，否则应提前用 `parser.parse` / `@babel/template` 构造好节点再替换。

## 5. insertBefore / insertAfter：插入兄弟节点

```js
FunctionDeclaration(path) {
  path.insertBefore(t.expressionStatement(t.stringLiteral("before")));
  path.insertAfter(t.expressionStatement(t.stringLiteral("after")));
}
// 输出:
+ "before";
  function square(n) { return n * n; }
+ "after";
```

参数为 **Statement 或 Statement 数组**（与 `replaceWithMultiple` 同一套启发式算法）。

## 6. unshiftContainer / pushContainer：容器数组插入 + 函数插桩实例

用于向节点里**数组类型**的属性（最典型 `body`）开头/末尾插入：

```js
FunctionDeclaration(path) {
  const body = path.get('body');   // BlockStatement 的 path
  body.unshiftContainer('body', t.debuggerStatement());  // 函数体开头插入
  body.pushContainer('body', t.debuggerStatement());     // 函数体末尾插入
}
```

**典型应用——函数插桩（埋点）**，注意箭头函数可能没有函数体：

```js
'ClassMethod|ArrowFunctionExpression|FunctionExpression|FunctionDeclaration'(path, state) {
  const bodyPath = path.get('body');
  if (bodyPath.isBlockStatement()) {
    // 有函数体：直接在开头插入埋点
    bodyPath.unshiftContainer('body', state.trackerAST);
  } else {
    // 没有函数体（如 ()=>0）：包成 blockStatement，保留原返回值
    bodyPath.replaceWith(
      template.statement(`{ ${state.trackerId}(); return PREV_BODY; }`)({ PREV_BODY: bodyPath.node })
    );
  }
}
// const test = () => 0   →   const test = () => { tracker(); return 0; }
```

## 7. remove / dangerouslyRemove

```js
path.remove();              // 删除当前节点（及所有子节点）
path.parentPath.remove();   // 删除父节点
```

- `dangerouslyRemove()`：节点本身是 falsy 时用（等价于 `remove` 的宽松版，不检查）。
- **删除会触发引用计数**：被删函数里用到的变量，其 binding 的 `references` 会相应减少——这就是"删完函数后自动能判断变量有没有人用"的机制（配合 [06 篇](./06-函数作用域与绑定.md) 的 `references === 0`）。

## 8. 边界情况与坑

1. **`console.xxx` 作为操作数不能直接删**：
   ```js
   var a = console.log('x') + 1;
   ```
   直接 remove 调用会留下 `var a = + 1;` → 生成阶段语法错误。**兜底**：包 try/catch，失败就 `path.replaceWith(t.identifier('undefined'))`。

2. **遍历中删除多个兄弟节点**：正向遍历数组时删除会导致**下标错位漏删**。对策：在 `exit` 阶段删（自下而上），或先收集 `paths` 数组再统一 `remove()`，或倒序遍历。

3. **替换后防止死循环**：visitor 里 `replaceWith` 生成的同类节点会被**再次遍历**。若你的替换逻辑对新节点又匹配（如把 `a+b` 换成 `a+b` 的包装），就死循环了 → 替换后 `path.skip()`；整棵树都不需要继续 → `path.stop()`。

4. **操作父节点**：`path.parent` 只能读，**改/删/换父节点必须用 `path.parentPath`**。

5. **同一容器内连插多次**：`insertBefore` 连续调用时后插入的排前面；要严格顺序用数组一次传入或依次 `insertAfter`。

6. **替换节点复用问题**：同一个 node 对象插到两处，AST 会共享引用，后续改一处另一处跟着变 → 用 `t.cloneNode(node, true)` 深拷贝。

7. **表达式位置多语句**：见第 3 节——表达式位置（如 `return` 的参数、二元运算的操作数）想塞多条语句，先把整个表达式所在的**语句**整体替换。

## 9. 完整实例：代理函数内联（反混淆高频操作）

"把 `function f(x,y){return x+y}` 的所有调用点换成 `x+y`，再删掉 f"：

```js
traverse(ast, {
  FunctionDeclaration(path) {
    const { node } = path;
    // 只处理"单条 return 语句"的简单函数
    if (node.body.body.length !== 1) return;
    const stmt = node.body.body[0];
    if (!t.isReturnStatement(stmt)) return;

    const name = node.id.name;
    const binding = path.scope.getBinding(name);
    if (!binding || !binding.constant) return;

    // 1) 替换所有调用点
    for (const ref of binding.referencePaths) {
      if (ref.parentPath.isCallExpression() && ref.parentKey === 'callee') {
        // 形参 → 实参映射后替换函数体
        const argMap = new Map(
          node.params.map((p, i) => [p.name, ref.parentPath.node.arguments[i]])
        );
        // 深拷贝返回表达式，并把里面的形参替换为实参
        const newExpr = t.cloneNode(stmt.argument, true);
        // （简化：这里假设实参都是简单表达式）
        ref.parentPath.replaceWith(substituteParams(newExpr, argMap));
      }
    }
    // 2) 删除函数声明
    path.remove();
  }
});
```

> 完整实现要处理：实参是复杂表达式（需先提变量避免重复求值）、形参被修改、闭包引用外层变量等情况——这些正是"简单函数内联、复杂函数保留"的原因（见 [09 篇](./09-AST反混淆实战.md) 6.3 节）。
