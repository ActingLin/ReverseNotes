# 04 · 节点转代码（AST → 源码字符串）

> 原笔记 4.5 节的深度展开，内容由网上资料补充（generator 源码分析、选项全表、生成器对比）
> 上一篇：[03-Babel核心API](./03-Babel核心API.md) ｜ 下一篇：[05-执行函数与求值](./05-执行函数与求值.md)

## 1. 这一步在反混淆中的位置

```
parse → transform → generate
        （改 AST）    （节点转回代码）← 本文主题
```

`generate` 看似简单（一句话 `generator(ast).code`），但反混淆里有两个高频进阶用法：

1. **提取局部节点源码**：只把某个函数/表达式节点转成代码字符串，拿去沙箱执行（衔接 [05-执行函数与求值](./05-执行函数与求值.md)）。
2. **控制输出格式**：还原后代码可读性、行号保留（配 sourcemap 调试）、注释保留。

## 2. 基本用法

```js
import { parse } from "@babel/parser";
import generate from "@babel/generator";

const ast = parse(code);
const output = generate(ast, { /* options */ }, code);
// output.code 为生成的代码字符串
// output.map  为 source map（需开启 sourceMaps: true）
```

**重要认知：空白、换行等格式符号不保存在 AST 里**（它们只在 `loc`/`extra` 中留下位置线索），所以生成的代码格式与源码**不保证一致**——反混淆里这反而是好事：乱成一团的混淆代码 generate 出来就是整齐的。

## 3. 内部架构（三层，理解后看选项不再懵）

generator 源码分三层（参考[知乎源码分析](https://zhuanlan.zhihu.com/p/597534030)）：

| 层 | 职责 |
|----|------|
| **Buffer 层** | 维护最终 code 字符串 `_buf` 和队列 `_queue`，提供 `append` 等底层方法，负责位置追踪与 source map 生成 |
| **Printer 层** | 中间抽象层：按 `node.type` 把节点分发（路由）到对应生成函数；负责缩进、空格、换行、注释定位、**括号判定**（运算符优先级、箭头函数参数、export default 表达式等） |
| **Generator 层** | 顶层对外 API |

流程：从 `File`/`Program` 开始 → 按 `Node.type` 递归调用对应生成函数 → 不断向 `_buf` 追加 → 返回。

> 括号判定是 Printer 的核心难点：`generate` 一个裸节点时（如 `path.node`），生成器不知道它嵌入的上下文，可能**少括号**（如运算符优先级变化）。所以"局部节点转代码"时要么用 `path.toString()`（会参考上下文），要么给节点补一个安全的语句/表达式外壳。

## 4. generate 选项速查表

来源：[Babel 官方文档](https://babel.nodejs.com.tw/docs/babel-generator#options)

**输出格式化：**

| 选项 | 默认 | 说明 |
|------|------|------|
| `comments` | `true` | 是否在输出中包含注释 |
| `compact` | `opts.minified` | `true` 则不添加空白；`'auto'` 按行长度自动 |
| `concise` | `false` | 减少空白（程度不如 compact） |
| `minified` | `false` | 是否压缩输出 |
| `retainLines` | `false` | 尽量保持与源码相同的行号（**保留堆栈跟踪/调试用**） |
| `retainFunctionParens` | `false` | 保留函数表达式周围的括号（可改变引擎解析行为） |
| `jsescOption` | - | 用 jsesc 处理字面值（如 `numbers` 存在时处理数字） |
| `jsonCompatibleStrings` | `false` | 输出 `"©"` 而非 `"©"`（JSON 兼容） |
| `shouldPrintComment` | 默认函数 | 自定义哪些注释输出；**默认保留含 `@preserve` / `@license` 的注释** |
| `auxiliaryCommentBefore` / `auxiliaryCommentAfter` | - | 输出文件开头/结尾附加块注释 |

**Source Map：**

| 选项 | 说明 |
|------|------|
| `sourceMaps` | 启用 source map 生成 |
| `inputSourceMap` | 输入 source map（多阶段转换链式映射） |
| `sourceRoot` | source map 中相对 URL 的根目录 |
| `sourceFileName` | 源码文件名（仅当第三参数 code 为字符串时使用） |

> 多来源 AST（多个 JS 文件拼成的树）：第三参数可传 `{ 文件名: 源内容 }` 对象，source map 就能反映正确来源。

## 5. 局部节点转代码：path.toString() 与 generate(node)

反混淆最常见的局部转代码场景：**提取解密函数源码拿去执行**（05 篇的沙箱执行就是靠它）。

```js
// 方式一：path.toString() —— 参考上下文，括号最安全
FunctionDeclaration(path) {
  const funcCode = path.toString();          // "function _0xae0a(a, b) {...}"
  fs.writeFileSync('decrypt.js', funcCode);
}

// 方式二：generate 单个节点 —— 输出与该节点类型对应的代码
const { code } = generate(path.node);        // 同样是函数源码

// 方式三：只转一个表达式
const { code } = generate(t.binaryExpression('+', t.numericLiteral(1), t.numericLiteral(2)));
// code === "1 + 2"
```

**建议**：
- 节点原本就在 AST 里有位置 → `path.toString()`（括号、缩进都参考上下文，最稳）
- 手工构造/克隆出的孤立节点 → `generate(node)`，再小心处理括号

## 6. 其他代码生成器：escodegen / recast / astring

| 生成器 | 配套解析器 | 特点 | 与 Babel 混用风险 |
|--------|-----------|------|------------------|
| `@babel/generator` | `@babel/parser` | Babel 生态，插件体系完整 | **逆向首选，配对使用无风险** |
| `escodegen` | esprima | 标准 ESTree 输出 | **高风险**：节点字段名与 Babel 不同（如 ESTree 用 `Literal`，Babel 用 `StringLiteral`），混用会丢注释甚至报 `Cannot read property 'name' of undefined` |
| `recast` | 任意（含 Babel） | **尽量保留原始格式**（空格、换行、引号风格） | 低；需要"最小 diff 修改"（如只改一行）时用它 |
| `astring` | 标准 ESTree | 体积小、速度快 | 中：缺 Babel 插件体系，Babel 扩展节点（如 Flow/TS）不支持 |

**结论**：反混淆主线用 `@babel/parser` + `@babel/generator`（同一套 AST 规范，注释/leadingComments 等元信息全保留）。只有"尽量不改动格式"的需求（如自动修 bug 只 diff 一行）才考虑 recast。

## 7. 反混淆场景的生成注意事项

1. **修改节点先深拷贝**：用 `t.cloneNode()` 而不是直接赋值，避免复用的节点被多处共享导致副作用。
2. **改完必须 generate 再写回**：忘了 generate 直接写回文件，写的就是原始源码（改动全丢）。
3. **需要保留行号**：开 `retainLines: true`（配合 `compact`），用于还原前后对拍 / 浏览器断点调试。
4. **删除节点后生成报错**：语法不完整（如删了二元表达式的一边），生成阶段才暴露 → 用 07 篇的"替换为 undefined"兜底。
5. **字符串转义**：`jsonCompatibleStrings`/`jsescOption` 控制 Unicode 转义输出（还原中文混淆字符串时常用）。
