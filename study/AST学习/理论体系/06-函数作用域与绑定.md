## 1. 基础概念：词法作用域、Binding、Reference

JavaScript 采用**词法作用域**：按源代码的**词法结构**（而不是运行时调用栈）确定作用域。

- **绑定（Binding）**：在某个作用域里**新建**的变量、函数、类、函数参数等标识符。如 `var a = 123` 中的 `a`、`function test(a, b) {}` 中的 `test` 和形参 `a`、`b`。
- **引用（Reference）**：对绑定的**使用**。如 `a + 1` 里的 `a`。

反混淆里最核心的两个判断都靠它们：
1. **这个变量安全吗？**（能不能折叠/删除）→ 看 binding 的 `constant`、`references`
2. **改名会不会撞名？** → 看 binding 的 `referencePaths` 和各级 scope

## 2. Scope 对象

通过 `Path` 对象的 `scope` 字段获取：

```js
{
  path: NodePath;        // 当前路径
  block: Node;           // 所属词法区块节点（函数节点、块语句节点等）
  parentBlock: Node;     // 所属父级词法区块节点
  parent: Scope;         // 指向父作用域
  bindings: { [name: string]: Binding };  // 该作用域下所有绑定
  uid: number;           // 作用域唯一标识（防止重复处理同一作用域）
}
```

## 3. scope 常用方法表

| 方法 | 作用 |
|------|------|
| `scope.bindings` | 当前作用域所有绑定，键为变量名，值为 `Binding` |
| `scope.getBinding(name)` | 取某变量的 binding（沿作用域链**向上找**）；找不到返回 `undefined` |
| `scope.getOwnBinding(name)` | 只看**当前作用域自身**的绑定 |
| `scope.getAllBindings()` | 当前及子作用域全部绑定 |
| `scope.hasBinding(name)` | 作用域链上是否有该绑定 |
| `scope.hasOwnBinding(name)` | 当前作用域自身是否定义了该变量 |
| `scope.parentHasBinding(name)` | 父作用域是否已定义该变量（**改名检查用**） |
| `scope.hasReference(name)` | 当前节点是否有该标识符的引用 |
| `scope.rename(oldName, newName)` | 重命名（oldName 必须有 binding，否则无效） |
| `scope.generateUidIdentifier(name)` | 生成**不冲突**的唯一标识符 |
| `scope.traverse(node, opts, state)` | 只遍历当前作用域内的节点 |
| `scope.crawl()` | 重构 scope（大规模改动后建议调用） |

## 4. Binding 类属性表

```ts
class Binding {
  identifier: t.Identifier;    // 声明处的标识符节点
  scope: Scope;                // 所属作用域
  path: NodePath;              // 初始拥有 binding 的 path
  kind: "var" | "let" | "const" | "module";  // 声明类型
  referenced: boolean;         // 是否被引用
  references: number;          // 被引用的次数
  referencePaths: NodePath[];  // 所有【引用处】的路径 ← 替换时用它
  constant: boolean;           // 是否常量（从未被修改 = true）
  constantViolations: NodePath[];  // 所有【修改处】（赋值）的路径 ← 判断时用它
  // 以及 hasValue / value / hasDeoptedValue 等（babel 内部求值用）
}
```

## 5. referencePaths vs constantViolations（容易混，重点）

- **`referencePaths`**：所有**读取/引用**该标识符的地方 → 用于**批量替换**。
- **`constantViolations`**：所有**修改/赋值**该标识符的地方 → 用于**判断**。`constant === true` 表示从未被修改，`false` 表示有修改。
- **`referenced` 只关心是否被引用，与是否被赋值无关。**

```js
var a = 1;    // ← binding.path 在这里（声明处）
a = 2;        // ← 进 constantViolations（有修改 → constant: false）
console.log(a); // ← 进 referencePaths
```

## 6. binding.constant 与常量传播

判断"变量可以安全替换成值"的标准写法：

```js
const binding = path.scope.getBinding(name);
// 三个条件同时满足：
// ① binding 存在且 constant（从未被赋值修改）
// ② init 是字面量/可静态求值的表达式
// ③ 不在循环体内（循环体内每次迭代可能不同）
if (binding && binding.constant &&
    t.isLiteral(binding.path.node.init) &&
    !isInsideLoop(binding.path)) {
  // 把所有引用处替换为字面量
  for (const ref of binding.referencePaths) {
    ref.replaceWith(binding.path.node.init);
  }
}
```

> 与 02-实操 篇"引用计数法"（数引用次数、== 0 删除）是同一套机制的两种用法：**计数**判断"能不能删"，**constant** 判断"能不能折叠"。

## 7. 安全重命名：三步检查

AST 转换的前提是保证程序正确性，**Babel 不会自动检测命名冲突**，必须插件作者自己查。三个条件缺一不可（来源：[深入浅出 Babel](https://cloud.tencent.cn/developer/article/1521497)）：

1. **父作用域**是否已定义该新名 → `path.scope.parentHasBinding(newName)`
2. **当前作用域**是否已定义该新名 → `path.scope.hasOwnBinding(newName)`
3. **每个引用所在的作用域**里是否撞名（被遮蔽/遮蔽别人）→ 遍历 `referencePaths` 检查 `refNode.scope.hasBinding(newName)`

```js
FunctionDeclaration(path) {
  const firstParam = path.get('params.0');
  const currentName = firstParam.node.name;
  const currentBinding = path.scope.getBinding(currentName);

  let sname;
  while (true) {
    sname = gid();  // 生成候选名
    if (path.scope.parentHasBinding(sname)) continue;      // ① 父作用域冲突
    if (path.scope.hasOwnBinding(sname)) continue;         // ② 当前作用域冲突
    if (currentBinding.references > 0) {                   // ③ 引用处冲突
      let conflict = false;
      for (const refNode of currentBinding.referencePaths) {
        if (refNode.scope !== path.scope && refNode.scope.hasBinding(sname)) {
          conflict = true;
        }
      }
      if (conflict) continue;
    }
    break;
  }

  // 开始替换：声明处 + 所有引用处
  currentBinding.identifier.name = sname;
  currentBinding.referencePaths.forEach(p => (p.node.name = sname));
}
```

## 8. scope.rename 与变量遮蔽（shadowing）

**方式一（手动）**：如上例，直接改 `identifier.name` + `referencePaths`，适合"混淆改名"这种批量无脑场景：

```js
// 混淆式改名：把作用域里所有变量名换成随机串
if (scopeRecord[path.scope.uid]) return;  // 用 uid 防重复处理
for (let name in path.scope.bindings) {
  const item = path.scope.bindings[name];
  const newName = randomString();
  item.identifier.name = newName;
  item.referencePaths.forEach(ref => (ref.node.name = newName));
}
scopeRecord[path.scope.uid] = true;
```

**方式二（安全）**：`binding.scope.rename(oldName, newName)`。
内部由 `Renamer` 类实现：遍历 `ReferencedIdentifier` 替换所有引用，用 `bindingIdentifierEquals` 判断作用域边界，**遇到同名但不同绑定的作用域会 `skip()` 跳过**——所以它能正确处理变量遮蔽。

**变量遮蔽的坑**：内层函数重新声明了同名变量 `x` 时，内层 `x` 的引用**不属于**外层 binding 的 `referencePaths`。如果不用 binding 机制、直接"找所有同名 Identifier 改名"，就会把内层无关的 `x` 也改掉 → 逻辑错误。**所有按名字操作的逻辑都必须走 scope/binding，不能裸扫 Identifier。**

## 9. 反混淆实战场景

| 场景 | 用到的能力 |
|------|-----------|
| 常量传播/变量内联 | `binding.constant` + `binding.path.node.init` + `referencePaths` |
| 删除未引用变量/函数 | `binding.references === 0`（或 `!binding.referenced`） |
| 标识符还原（`_0x1a2b` → `temp1`） | `scope.rename` / 手动改 `identifier` + `referencePaths` |
| 判断变量是否被重新赋值（循环条件） | `binding.constantViolations.length` |
| 生成不冲突的临时变量 | `scope.generateUidIdentifier('tmp')` |
